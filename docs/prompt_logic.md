# プロンプト生成ロジック解説 (Project Wannabe 内部仕様)

このドキュメントは、Project Wannabe がユーザーの入力をどのように AI への指示へ変換しているかを説明します。

通常の利用では読む必要はありません。モデルの挙動を調整したい場合、プロンプト形式を確認したい場合、または wanabi 系モデル向けのデータ形式を理解したい場合の参考資料です。

主な参照コード:

* `src/core/prompt_builder.py`
* `src/core/context_utils.py`
* `src/core/dynamic_prompts.py`
* `src/core/thinking.py`
* `src/core/idea_processor.py`
* `src/core/autocomplete_manager.py`

## 1. 全体像

Project Wannabe は、本文や詳細情報をそのまま KoboldCpp に送っているわけではありません。

生成のたびに、現在のモード、本文の長さ、詳細情報、次の展開の指示、設定値を見て、AI が読みやすい形へ組み立て直します。

大まかな流れは次の通りです。

1. UI から本文・詳細情報・次の展開の指示・設定を集める
2. Dynamic Prompts とコメントアウトを処理する
3. 現在の生成が `GEN`、`CONT`、`IDEA` のどれに当たるか判定する
4. タスクに合わせて Instruction / Input / Assistant Prefill を作る
5. チャットテンプレモードに応じて、旧 wanabi 用プロンプトまたは Chat Completions messages に変換する
6. 必要に応じてコンテキスト長に収まるよう本文を圧縮する
7. KoboldCpp へ送信する

## 2. チャットテンプレモード

Project Wannabe には、AI への送り方が2種類あります。

| UI上の名称 | 内部値 | 送信先 | 主な用途 |
| :--- | :--- | :--- | :--- |
| 旧wanabiシリーズ | `mistral_legacy` | `/api/extra/generate/stream` | 旧来の wanabi 系モデル向け |
| 汎用 | `chat_completions_generic` | `/lcpp/v1/chat/completions` | モデル側のチャットテンプレートを使う汎用モード |

初回起動時のダイアログ、または `設定` > `生成パラメータ設定...` > `チャットテンプレモード` で選択します。

旧 wanabi シリーズでは、最終的に次のような Mistral Instruct 形式の文字列を作ります。

```text
[INST]{Instruction}
{Input}[/INST]{Assistant Prefill}
```

汎用モードでは、次のような Chat Completions messages を作ります。

```json
[
  {"role": "system", "content": "..."},
  {"role": "user", "content": "..."},
  {"role": "assistant", "content": "..."}
]
```

`assistant` メッセージは、本文の続きを自然につなぐための prefill として使われます。不要な場合は作られません。

## 3. UI から集める情報

プロンプト生成で主に使われる入力は以下です。

| UI | 内部での扱い |
| :--- | :--- |
| 本文エリア | `main_text` |
| 次の展開の指示 | `authors_note` |
| タイトル | `metadata.title` |
| キーワード | `metadata.keywords` |
| ジャンル | `metadata.genres` |
| あらすじ | `metadata.synopsis` |
| 設定 | `metadata.setting` |
| プロット | `metadata.plot` |
| セリフ量 | `metadata.dialogue_level` |
| レーティング | `rating` |
| System Prompt | `system_prompt` |
| 思考 prefill | thinking 関連処理で使用 |

メモ欄は、通常の生成プロンプトには含まれません。必要な内容は、本文や詳細情報へ移して使います。

## 4. Dynamic Prompts の処理タイミング

Dynamic Prompts は、プロンプトの部品を作る前に処理されます。

処理対象の例:

* 本文
* 次の展開の指示
* タイトル
* キーワード
* ジャンル
* あらすじ
* 設定
* プロット
* System Prompt

処理順は次の通りです。

1. `@//` と `@/* ... @*/` のコメントを削除
2. `@break` / `@startpoint` / `@endpoint` で有効範囲を切り出し
3. `{A|B|"C D"}` からランダムに1つを選択

たとえば、本文に次のように書かれているとします。

```text
第一章の古い本文

@break

彼女は{青い|黒い|銀色の}扉を見上げた。 @// 色はあとで調整
```

AI に渡る本文は、生成ごとに次のようになります。

```text

彼女は銀色の扉を見上げた。 
```

## 5. タスク判定

Project Wannabe は、現在のモードと本文の状態から内部タスクを決めます。

内部タスクは大きく分けて3種類です。

| タスク | 意味 |
| :--- | :--- |
| `GEN` | 新しい本文、または短い書き出しから本文を生成する |
| `CONT` | 既存本文の続きを生成する |
| `IDEA` | タイトル、あらすじ、設定、プロットなどのアイデアを生成する |

実際には、詳細情報があるかどうかで `_INFO` と `_ZERO` に分かれます。

| モード | 本文の状態 | 詳細情報 | 内部タスク |
| :--- | :--- | :--- | :--- |
| `generate` | 空 | あり | `GEN_INFO` |
| `generate` | 空 | なし | `GEN_ZERO` |
| `generate` | 有効1〜3行 | あり | `GEN_INFO` |
| `generate` | 有効1〜3行 | なし | `GEN_ZERO` |
| `generate` | 有効4行以上 | あり | `CONT_INFO` |
| `generate` | 有効4行以上 | なし | `CONT_ZERO` |
| `idea` | 不問 | あり | `IDEA_INFO` |
| `idea` | 不問 | なし | `IDEA_ZERO` |
| `autocomplete` | generate と同様 | あり/なし | `GEN` または `CONT` |

有効行とは、空白を除いて1文字以上ある行です。

## 6. Instruction

内部タスクごとに、基本の Instruction が決まります。

```python
INSTRUCTION_TEMPLATES = {
    "GEN_INFO": "以下の情報に基づいて小説本文を生成してください。",
    "GEN_ZERO": "自由に小説を生成してください。",
    "CONT_INFO": "参考情報と本文を踏まえ、最後の文章の自然な続きとなるように小説を生成してください。",
    "CONT_ZERO": "本文を踏まえ、最後の文章の自然な続きとなるように小説を生成してください。",
    "IDEA_INFO": "以下の情報に基づいて、完全な小説のアイデア（タイトル、キーワード、ジャンル、あらすじ、設定、プロット）を生成してください。",
    "IDEA_ZERO": "自由に小説のアイデア（タイトル、キーワード、ジャンル、あらすじ、設定、プロット）を生成してください。",
}
```

最後にレーティングが付加されます。

```text
以下の情報に基づいて小説本文を生成してください。 レーティング: general
```

## 7. 詳細情報の整形

詳細情報は、次の順番で整形されます。

1. タイトル
2. キーワード
3. ジャンル
4. あらすじ
5. 設定
6. プロット
7. セリフ量

アイデア出しモードでは、セリフ量は含まれません。

整形例:

```text
# タイトル:
刻の迷宮

# キーワード:
時間逆行
迷宮
少女騎士

# ジャンル:
ファンタジー
サスペンス

# あらすじ:
時計塔の崩壊とともに、王都の時間が逆流し始める。
```

空欄の項目は出力されません。

## 8. `GEN` タスク

`GEN` は、本文が空、または有効3行以下のときに使われます。

### `GEN_INFO`

詳細情報がある場合、詳細情報を Input に入れます。本文がある場合は assistant prefill になります。

旧 wanabi モードの例:

```text
[INST]以下の情報に基づいて小説本文を生成してください。 レーティング: general
# タイトル:
刻の迷宮

# あらすじ:
時計塔の崩壊とともに、王都の時間が逆流し始める。[/INST]雨上がりの王都で、少女は止まった時計を見上げていた。
```

この場合、AI は `雨上がりの王都で...` の続きを書き始めることを期待されます。

### `GEN_ZERO`

詳細情報も本文もない場合は、自由生成になります。

```text
[INST]自由に小説を生成してください。 レーティング: general[/INST]
```

## 9. `CONT` タスク

`CONT` は、有効4行以上の本文があるときに使われます。本文の続きとして自然につなげるため、本文を大きく3つに分けます。

| 部品 | 意味 |
| :--- | :--- |
| `main_part` | 本文の古い部分 |
| `tail` | 直近の数行 |
| `assistant_prefill` | AI に続きを書かせる直前の書き出し |

### 文章が完結している場合

本文末尾が `。`、`」`、または改行で終わっている場合は、文章が完結していると見なします。

この場合:

* `assistant_prefill` は空
* `tail` は最後の有効行を含む最大3行
* `main_part` はそれより前の本文

例:

```text
時計の針が逆回転を始めた。
風景がぐにゃりと歪む。
壁に飾られた絵画の人物が、ゆっくりとこちらを向いた。
彼は息を呑んだ。
```

分割:

```text
main_part:
時計の針が逆回転を始めた。

tail:
風景がぐにゃりと歪む。
壁に飾られた絵画の人物が、ゆっくりとこちらを向いた。
彼は息を呑んだ。

assistant_prefill:
（空）
```

### 文章が途中で終わっている場合

本文末尾が文の途中で終わっている場合は、最後の有効行を assistant prefill にします。

例:

```text
時計の針が逆回転を始めた。
風景がぐにゃりと歪む。
壁に飾られた絵画の人物が、ゆっくりとこちらを向いた。
彼は口を開き、何かを伝えようとしている。
その唇が形作ったのは
```

分割:

```text
assistant_prefill:
その唇が形作ったのは

tail:
風景がぐにゃりと歪む。
壁に飾られた絵画の人物が、ゆっくりとこちらを向いた。
彼は口を開き、何かを伝えようとしている。

main_part:
時計の針が逆回転を始めた。
```

この構造により、AI は「その唇が形作ったのは」の直後から自然に続きを出しやすくなります。

## 10. `CONT` の Input 構造

`CONT` タスクでは、Input に複数のブロックを組み立てます。

### 参考情報ブロック

```text
【参考情報】
```
```text
# タイトル:
刻の迷宮

# あらすじ:
時計塔の崩壊とともに、王都の時間が逆流し始める。
```

### 本文ブロック

```text
【本文】
```
```text
時計の針が逆回転を始めた。
```

### 次の展開の指示ブロック

設定 `authors_note_display_mode` によって見出しが変わります。

デフォルト:

```text
【この先の展開についての指示・メモ】
```

レガシー:

```text
【オーサーズノート】
```

本文:

```text
主人公の焦りを強調する。
絵画の人物が味方なのか敵なのか分からない雰囲気にする。
```

### tail

最後に、直近の本文 `tail` をブロック外にそのまま置きます。

これは、AI に「この直前の文章につながるように書く」ことを強く示すためです。

## 11. 継続タスクのプロンプト順序

`設定` > `生成パラメータ設定...` > `継続タスクのプロンプト順序` で、参考情報と本文ブロックの順番を変えられます。

| 設定 | 内部値 | 順序 |
| :--- | :--- | :--- |
| 本文との整合性を優先 | `reference_first` | 参考情報 → 本文 → 次の展開の指示 → tail |
| 詳細情報との整合性を優先 | `text_first` | 本文 → 参考情報 → 次の展開の指示 → tail |

通常は `reference_first` で構いません。低いコンテキスト長で詳細情報を強く見せたい場合は、`text_first` が有効なことがあります。

## 12. `IDEA` タスク

`IDEA` は、アイデア出しモードで使われます。

本文エリアの内容は参照しません。詳細情報パネルのタイトル、キーワード、ジャンル、あらすじ、設定、プロットをもとに、足りない情報や新しい案を生成します。

### 全部を生成する場合

`生成項目` が `全部` の場合、タイトルからプロットまで一式を出すように指示します。

旧 wanabi モードの例:

```text
[INST]以下の情報に基づいて、完全な小説のアイデア（タイトル、キーワード、ジャンル、あらすじ、設定、プロット）を生成してください。 レーティング: general
# キーワード:
異世界
追放

# ジャンル:
ファンタジー[/INST]
```

### 特定項目だけを生成する場合

`タイトル` や `プロット` など、特定項目だけを選ぶと、`IdeaProcessor` が stop sequence や assistant prefill を調整します。

高速な手法（実験的）を使う場合は、選んだ項目の前に来る項目を prefill として補い、対象項目から出しやすくします。

思考モードが有効な場合、高速な手法は自動的に無効化されます。

## 13. オートコンプリート

リアルタイム提案では、内部的に `current_mode="autocomplete"` として扱われます。

特徴:

* 本文エリアのカーソル位置周辺を使う
* ゴーストテキストとして表示する
* `Tab` で確定、`Esc` で破棄
* 思考モードは使用しない
* 汎用モードでは、thinking control を OFF に寄せる

`CONT` 扱いになる本文では、最後の行が assistant prefill になり、自然にその続きを短く出すようにします。

## 14. コンテキスト圧縮

長い本文を扱う場合、プロンプト全体がモデルの最大コンテキスト長を超えることがあります。

Project Wannabe は KoboldCpp API を使って、利用可能なコンテキスト長を確認します。

使用する主な API:

* `GET /api/extra/true_max_context_length`
* `POST /api/extra/tokencount`

利用可能なプロンプト長は、概ね次のように計算します。

```text
利用可能コンテキスト = true_max_context_length - 最大出力長
```

### `token_dynamic`

推奨設定です。

1. プロンプト全体のトークン数を数える
2. 本文単体のトークン数を数える
3. 本文以外に必要なトークン数を推定する
4. 収まる範囲まで本文の古い部分を削る
5. 収まるまで KoboldCpp の tokencount で確認する

本文の後ろ側、つまり直近の文脈を残すことを優先します。

### `char_trim`

指定した最大本文文字数に合わせて、本文の先頭を削ります。

トークン数ではなく文字数ベースなので単純ですが、モデルや言語によるトークン差を見ません。

### `none`

圧縮しません。

コンテキスト超過した場合は、UI 側でエラーとして生成を止めます。通常は推奨しません。

## 15. 思考モード

思考モードは `src/core/thinking.py` で制御されます。

有効になる条件:

* チャットテンプレモードが `chat_completions_generic`
* リクエスト種別が `generate` または `idea`
* ツールバーの思考モードが ON
* Thinking Template が無効化されていない

無効になる主な条件:

* `mistral_legacy` モード
* `autocomplete`
* Thinking Template が `disabled`
* assistant prefill と衝突し、設定上 prefill 思考を扱えない場合

Gemma 4 系テンプレートでは、思考ON/OFFを制御するために system 側へ次のような制御文字列を入れます。

```text
<|think|>
```

または:

```text
<|no_think|>
```

思考が出力された場合、生成候補カードの「思考」欄に分けて表示されます。

## 17. 生成結果の表示

プロンプト生成そのものとは別ですが、出力は中央の生成候補カードに表示されます。

* 通常本文はカード本文へ表示
* 思考出力は「思考」欄へ表示
* `本文へ挿入` で本文へ転記
* `メモへ送る` でメモ欄へ転記
* アイデア出しの `# タイトル:` などは、詳細情報の `← 転記` で各欄へ転記

現在は候補カードを中心に、生成結果を確認してから本文やメモへ移します。
